## 需求目的

按 MegaXcess / PAGCOR 最新确认的规则，把游戏的平台分类（平台名称）统一为 NG / eBINGO / EGAMES 三类，并让后台、API、注单、报表、导出和 PAGCOR 报送数据使用同一份分类。

- **现状问题**：系统内部分游戏的平台分类与 PAGCOR 规则不一致；后台各处写法也不统一（对局查询用 ng / E-Game / E-Bingo，三方游戏统计用 e-game / ng / e-bingo），影响 PAGCOR 审计抽成对账。
- **本次目标**：
    1. 全量检查并修正现有游戏的平台分类；
    2. 在【游戏入口设置 > 游戏配置】中新增「平台名称」字段、查询条件和维护入口，分类按名单自动判定、不能随意改；
    3. 注单、报表、导出、API 统一使用新分类，并对受影响的历史数据做修复和核对；
    4. 后续新增游戏按同一规则归类，避免再次出现分类错误和报表数据迁移。
- **原型**：画布「PAGCOR游戏分类需求」，可在 Play 模式下操作全部交互。

## 分类规则

平台名称只有 3 个取值：**NG**（7 款）、**eBINGO**（13 款），其余符合范围的电子娱乐场游戏一律为 **EGAMES**。名单以 MegaXcess / PAGCOR 确认版本为准。

- **判定键**：游戏厂商 + 游戏ID。命中 NG 名单 → NG；命中 eBINGO 名单 → eBINGO；都不命中 → EGAMES。不按游戏名称判定（名称可能被运营改或存在同名）。
- **名单存储**：作为系统配置表维护，后台只读展示；名单变更需走技术配置 + 审批，并触发一次全量校验。
- **写法统一**：后台、API、导出一律使用 `NG` / `eBINGO` / `EGAMES`。

## 页面说明

### 1. 游戏配置 · 列表

- **新增列「平台名称」**：放在「游戏类别」之后，用色块标签显示 NG / eBINGO / EGAMES。
- **分类异常标记**：当前分类与名单判定结果不一致时，单元格标红，显示「分类异常 应为 X」。上线并完成数据修复后，正常情况下不应再出现。
- **「仅看分类异常 (N)」按钮**：点击后列表只显示异常游戏，N 为全量异常数（不受分页影响）；再点一次取消。用于上线后的全量检查和日常巡检。
- **「PAGCOR分类名单」按钮**：打开只读弹窗，展示 NG 7 款、eBINGO 13 款名单及说明「名单外一律为 EGAMES」。
- **排序与分页**：沿用现有逻辑。

### 2. 游戏配置 · 查询条件

- **新增「平台名称」下拉**：放在「游戏类别」之后，选项为 平台名称（全部，默认）/ NG / eBINGO / EGAMES，单选。
- **搜索 / 重置**：点「搜索」后才生效；「重置」清空该条件。与其他查询条件是“且”的关系。
- **无结果**：显示「暂无数据」。

### 3. 添加游戏 / 编辑游戏弹窗

两个弹窗字段相同；点「添加游戏」弹出空表单，点列表「编辑」弹出带出该行数据的表单。除「平台名称」外，其余字段沿用现有逻辑。

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 平台名称（新增） | 是 | 下拉：NG / eBINGO / EGAMES，放在「游戏类别」之后 |
| 自动带出 | — | 选择游戏厂商、填写游戏ID后，按名单自动带出平台名称 |
| 选项限制 | — | 名单内游戏只能选对应分类；名单外游戏只能选 EGAMES；其他选项置灰不可选 |
| 不一致提示 | — | 编辑历史数据时，若当前分类与名单不符，字段下红字提示「当前分类与PAGCOR分类名单不一致，该游戏应为 X」，不改对不能保存 |
| 字段说明 | — | 灰字：按「游戏厂商 + 游戏ID」对照PAGCOR分类名单自动带出：名单内游戏只能选对应分类，名单外游戏只能选EGAMES |
| 未选提示 | — | 点「确定」时为空：「请选择平台名称」 |

- **保存后**：提示「添加成功 / 编辑成功」，列表刷新，更新时间取保存时间（后台显示 −04:00）。
- **服务端兼底**：前端限制之外，接口必须再校验一次；不符合名单的分类直接拒绝，返回明确错误码。

### 4. 第三方对局查询(结算时间) / 第三方对局查询

- **查询项「平台名称」**：选项改为 平台名称（全部）/ NG / eBINGO / EGAMES，去掉 Special Game。
- **列表列「平台名称」**：显示注单上记录的平台分类，写法同上。
- **导出**：导出文件中的平台名称与页面一致。

## 数据与接口

分类只有一个来源：名单配置表。游戏表存判定结果，注单存结算时的分类快照，报表、导出、PAGCOR 数据都从注单快照取数，不再各自维护游戏清单。字段名为建议，以技术方案为准。

| 对象 | 改动 |
| --- | --- |
| 名单配置表（新增） | 如 `pagcor_game_category_list`：厂商编码、游戏ID、游戏名称、版本、分类（NG / eBINGO）、生效时间、状态。只存 NG / eBINGO，不在表内即 EGAMES |
| 游戏表 | 新增 `platform_category`，枚举 NG / eBINGO / EGAMES，非空；新增、编辑、厂商同步入库时都按名单计算 |
| 厂商游戏同步任务 | 新游戏入库自动判定，不在名单内默认 EGAMES；不允许出现空值 |
| 注单（第三方对局） | 新增 `platform_category` 快照，结算写入时取游戏当前分类；替换原「平台名称」的 ng / e-game / e-bingo / Special Game 取值 |
| 后台接口 | 游戏列表、游戏详情、注单查询返回 `platform_category`，并支持按它筛选；保存游戏接口服务端校验分类 |
| 对外 / 前台 API | 涉及游戏分类的字段统一为 NG / eBINGO / EGAMES，需技术排查全部调用方 |
| 三方游戏统计（e-game / ng / e-bingo） | 改为按注单 `platform_category` 分三张表统计；字段口径不变（游戏类型、供应商、投注、派彩、审计费用，默认真实用户，金额 2 位小数，CSV 进【报表下载】） |
| 导出 | 所有带平台名称的导出文件同步新写法 |
| 缓存 | 游戏分类、名单有缓存的，变更后主动刷新 |

- **注单要存快照**：名单以后可能调整，存快照可保证已报送的 PAGCOR 数据能复现。名单变更是否追溯历史注单，每次单独评审。
- **游戏类别不动**：「游戏类别」（Hot / Slot / Bingo 等，用于前台入口）与「平台名称」（PAGCOR 分类）是两个独立字段，本次不改前者。

## 历史数据修复与核对

上线后先修游戏配置，再按确认的范围回刷注单和报表，最后与 MegaXcess / PAGCOR 对账。每一步都要留存修改前后清单。

1. **全量检查**：导出全部游戏的「厂商 + 游戏ID + 游戏名称 + 当前分类 + 名单判定分类」，列出不一致清单，交产品和运营确认。
2. **名单核对**：确认 7 款 NG、13 款 eBINGO 在系统内都能找到对应游戏；找不到的单独列出，不能默认跳过。
3. **修正游戏配置**：按名单批量更新游戏表 `platform_category`，其余全部置为 EGAMES；记录操作日志。
4. **回刷注单**：对确认范围内的历史注单重算分类快照；起始日期由产品与技术确认。
5. **重生成报表**：重新生成受影响区间的三方游戏统计（NG / eBINGO / EGAMES），旧文件保留不覆盖。
6. **对账**：按天、按分类比对修复前后的投注、派彩、审计费用；三类合计应保持不变，只是在分类之间转移。差异清单交财务 / 合规与 MegaXcess 确认。

- **报表口径**：按本地时区 UTC+8 自然日（0:00:00–23:59:59）统计，过滤测试用户（Test 前缀），金额保留 2 位小数。
- **执行方式**：脚本先在 QA 环境跑一遍，结果确认后再上生产；生产执行选低峰时段，并准备回滚脚本。

## 边界与异常

| 场景 | 处理 |
| --- | --- |
| 游戏ID在名单内，但厂商不是名单对应厂商 | 不命中，归 EGAMES；判定必须是「厂商 + 游戏ID」同时匹配 |
| 同名但游戏ID不同（如不同版本） | 按游戏ID判定；NG 名单标注 V. 1，后续新版本默认 EGAMES，需名单更新才归 NG |
| 运营改了游戏名称 | 不影响分类 |
| 编辑游戏时改了厂商或游戏ID | 重新按名单判定并带出平台名称 |
| 打开分类错误的历史游戏编辑 | 红字提示应为 X，改对才能保存 |
| 绕过前端直接调接口保存错误分类 | 服务端拒绝并返回错误码 |
| 厂商同步新游戏时名单表不可用 | 不写空值；该游戏暂不入库或标记待处理并告警，技术选定其一 |
| 已停用 / 已删除的游戏 | 同样修正分类，历史注单仍需正确归类 |
| 跨日注单（下注与结算不在同一天） | 快照以结算写入时为准，报表按现有口径归日 |
| 名单日后变更 | 技术配置 + 审批后生效；触发全量校验；是否追溯历史注单单独评审 |
| 平台名称筛选与「仅看分类异常」同时使用 | 两个条件同时生效（“且”） |

## 验收标准

- [ ] 游戏配置中恰好 7 款游戏为 NG、13 款为 eBINGO，与名单逐条一致；其余游戏全部为 EGAMES，没有空值。
- [ ] 修复完成后，「仅看分类异常」数量为 0。
- [ ] 按平台名称筛选，列表只显示对应分类的游戏；重置后恢复全部。
- [ ] 添加游戏时，选厂商、填游戏ID后自动带出平台名称；名单内游戏选不了其他分类，名单外游戏只能选 EGAMES。
- [ ] 编辑分类错误的历史游戏时出现红字提示，不改对无法保存；改对后列表同步更新。
- [ ] 直接调用保存接口提交错误分类被拒绝。
- [ ] 厂商新同步的游戏自动得到正确分类。
- [ ] 对局查询（下注时间 / 结算时间）的平台名称选项为 NG / eBINGO / EGAMES，没有 Special Game；列表和导出一致。
- [ ] 三方游戏统计三张报表按新分类取数；修复前后同一天三类合计的投注、派彩、审计费用不变。
- [ ] 后台、API、注单、报表、导出的分类写法全部为 NG / eBINGO / EGAMES。
- [ ] 涉及的数据修改和游戏编辑都有操作日志（操作账号、时间、修改前后值）。

## 覆盖范围

- **管理后台**（PC）：游戏配置、对局查询、三方游戏统计及相关导出。
- **服务端**：名单配置、游戏表、厂商同步、注单、报表任务、API。
- **C 端**（H5 / PC / PWA / Android APP / iOS / Maya · Glife 小程序）：无页面改动，前台游戏入口仍按「游戏类别」展示。若前台接口返回了分类字段，需确认没有依赖旧取值。
- **代理后台**：如报表按平台分类统计，需同步口径（待确认）。
